# 平台自有 Jio 链接供应商

用户已于 2026-10-20 在聊天中确认单商品方案。

## 范围

新增平台自有供应商，展示名称为“Jio（自有）”，内部标识为 `local`。只有一个固定的 Jio 链接商品，不增加多商品配置。管理入口位于现有 Jio 供应商页面，沿用当前页面样式。

## 价格和调度

供应商商品价格由管理员配置，单位沿用供应商采购价格 USD；客户端销售价格继续沿用现有 Jio 价格管理规则。价格必须是有限的正数，存储精度沿用现有金额规则。

接入现有供应商启用、禁用、指定供应商和自动最低价策略。自有供应商不需要 API 密钥、上游充值或账户余额；其可用条件是已启用、价格有效且有未发放库存。仅对自有供应商免除上游余额条件，不改变其他供应商的余额检查。新供应商默认禁用，配置后可手动启用。库存、价格或启用状态变化后使报价缓存失效。

## 链接库存

新增 `jio_links` 数据表，保存链接、用于去重的链接摘要、未使用/已发放状态、关联订单标识、创建时间和发放时间。链接摘要建立唯一约束，避免重复导入已发放链接。库存数量来自未使用记录。

批量录入使用多行文本框，一行一个链接，兼容 Windows 和 Unix 换行，清理首尾空白并忽略空行。只接收合法的 HTTP/HTTPS URL，不访问输入的链接。链接内容保持不变，避免破坏签名参数。单次最多 1000 条，每条最多 4096 字节，并限制请求体大小。

无效行存在时整批拒绝并报告行号；合法批次跳过批内和已有重复链接，返回新增数和重复数。数据库异常时回滚本批导入。页面提供分页列表、状态筛选、库存统计和批量录入入口。链接仅由已认证管理员查看，不写入普通日志。

## 兑换和一致性

通过现有 JioProvider 接口返回固定商品、配置价格和真实库存。购买时通过数据库事务锁定可用库存，并同时记录订单及发放状态，防止并发重复发放。相同幂等标识重试返回原交付结果，不消耗新链接；不同订单不能获取同一库存记录。

适配现有卡密兑换、后台测试购买和订单结算流程。事务失败不扣库存；库存不足返回明确错误。成功发放后即使后续响应丢失也保留发放记录，重试可恢复结果，不自动将链接释放给其他订单。数量购买必须全部满足，否则整单失败。

## 验证

验证批量录入的换行、空行、无效 URL、重复链接及请求限制；验证定价校验、无库存及禁用状态；验证事务回滚、并发领取与幂等重试；验证自有供应商参与自动选择且外部供应商仍须满足余额条件。运行相关 Go 测试和构建，并检查后台页面脚本及操作流程。

## 实施边界

保留工作区已有 Grizzly、异步兑换及供应商状态修改，在其基础上增量接入，不覆盖现有工作。不引入多商品、链接有效性外部检测或新的客户端销售价格体系。
